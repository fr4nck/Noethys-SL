- Base de modification : branche `wx` `ec6d5e5a737b1d1362081fa29d2520e5e195d519`.

## Perimetre du correctif
- Propriete explicite `parent` pour les fenetres de selection, recherche, progression et erreur de `Facturation.Impression`. L'appelant `DLG_Factures_email` transmet son dialogue visible ; les autres appelants conservent le parametre facultatif `None` pour compatibilite.
- Un `finally` detruit le Mailer meme si `ShowModal` echoue et supprime les PDF temporaires du lot y compris en cas de sortie anticipee, erreur de resolution d'adresse ou fermeture anormale du dialogue. La connexion de lecture des adresses est fermee dans un `finally`.
- Une seule operation diagnostique anonyme `factures.preparation`, facultative, mesure la duree de construction et generation. Aucun nom, montant, adresse, PDF, chemin ou SQL journalise.
- Tests avec base/serveurs simules, sans email ni acces PMSL.

## Limites a qualifier
- **La correction est limitee a l'ownership et au cycle de vie des fenetres**. `Facturation.__init__`, `GetDonneesImpression` et le rendu des PDF restent synchrones sur le thread wx : un gel prolonge peut donc subsister.
- Le moteur `UTILS_Impression_facture` partage des variables globales ; `DLG_Noedoc.ModeleDoc` peut utiliser des objets `wx.Image`/`wx.Bitmap`. Deplacer naivement l'ensemble en worker serait dangereux. Qualifier les traitements purs, les requetes SQL et une generation serialisee avant une evolution asynchrone.
- Un PDF temporaire partiellement ecrit **pendant une erreur de generation** peut echapper au nettoyage si la fonction retourne `False` sans fournir son chemin : garde distincte a developper avant GO.
- Aucun test de recette Windows sur le poste utilisateur n'est revendique ici. L'issue #432 doit rester ouverte ; pas de tag, build ni release.

## Validation requise
- CI Windows rapide, `tests.test_ui432_factures_proprietaire`.
- Recette Windows GUI sur vrai `wx.Frame` maximise : observer `IsIconized`, `IsMaximized`, `IsHungAppWindow` et `GW_OWNER` pendant preparation et envoi factice.
- Test de charge PDF unitaire et lot ; verifier reactivite et absence de fenetre fantome avec donnees fictives.
- Prochaine RC uniquement apres qualification Connecthys et facturation, sans double envoi.
