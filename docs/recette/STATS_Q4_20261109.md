## Constats nécessitant une décision métier

1. **QF multi-types (arbitrage [#442](https://github.com/fr4nck/Noethys-SL/issues/442)) :** une famille peut avoir plusieurs `IDtype_quotient` valides. Les valeurs différentes vont à `a_verifier`, les valeurs égales de types distincts sont agrégées numériquement. Le choix du bon type selon activité, barème et date **n'a pas été approuvé**.

4. **Scolarité / Ancienneté :** le mode Inscrits retourne des listes vides dans le code actuellement testé. Il reste à vérifier si ce comportement est attendu.
5. **Géographie :** distances simulées localement ; pas de trafic vers un service tiers ni test du blocage réseau synchrone.

- Une preuve du premier banc ne qualifie que ces deux parcours SQL/metier, pas leurs rendus sous wx installe ni les 31 autres objets. Consigner le run CI et le SHA avant tout PASS.

### Q4-B — les 31 objets restants et MySQL

- Etendre la fixture aux 11 pages, une classe a la fois, avec jeu de donnees connu ; traquer doublons, comptes payeurs, periodes, dates de naissance manquantes, valeurs nulles, tris et totaux.

- Tester chaque cache reel, et non seulement le cache transversal ; ne jamais supposer qu'un objet passe parce qu'un voisin partage sa classe parente.
- Conserver les resultats red/green et les exemples limites dans la matrice.

### Q4-QF — regle metier obligatoire avant GO

- Le code de validite `UTILS_Quotients_validite.py` recherche les chevauchements **par `IDtype_quotient`**, donc plusieurs types valides peuvent coexister.
- `UTILS_Stats_familles._QuotientsAlaDate()` determine une valeur numerique unique par famille, independamment du type ; des valeurs differentes simultanement valides vont vers `a_verifier`. Des valeurs egales de types differents sont aujourd'hui fusionnees numeriquement. **Ce mecanisme n'est pas une politique metier validee.**
- **Decision a prendre** : choix explicite de type si les activites ne partagent pas le meme referentiel ; interpretation d'un ensemble multi-activites/multi-baremes ; date de reference des inscrits et des presents ; cas de QF absent, nul ou invalide.
- En l'absence de decision, **interdit** de choisir arbitrairement un type, de faire une moyenne, d'utiliser une valeur issue d'une autre activite ou de reclasser `a_verifier` comme QF zero. Conserver le comportement prudent existant et le STOP-GATE metier.
- Tests d'acceptation a concevoir sur types actifs egaux/differents, bornes inclusives, changement de periode, references successives, deux comptes payeurs, familles sans QF et plusieurs activites de baremes distincts.
