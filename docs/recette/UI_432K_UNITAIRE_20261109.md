## Intervention reelle
- `noethys/Utils/UTILS_Travail_long.py` : traitement de lecture sur worker Python, dialogue modal avec proprietaire wx explicite et timer GUI, resultat via file synchronisee. Le worker n'effectue aucun appel wx.
- `UTILS_Facturation.GetDonneesImpression` : delegation au worker seulement quand le parent wx est visible et que la source de base est connue. Connexion nouvelle dans le worker avec `pooling=False`, fermee sous `finally`. Les autres appels continuent en mode historique.
- L'annulation abandonne le resultat et stoppe la suite (pas d'envoi de facture) sans tuer le worker SQL en cours. Aucune operation ecrivant dans la DB n'est autorisee dans cet executant.
- `tests/test_ui432k_factures_lecture.py` : cinq tests de contrat simules, DB et transport fictifs ; `tests/test_ui432k_worker_win32.py` : une lecture fictive de 8 s, vrais HWND, maximisation, proprietaire Win32, tick wx, aucune base reelle.
