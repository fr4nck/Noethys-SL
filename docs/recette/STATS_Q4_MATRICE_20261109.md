## Garde-fous d'interpretation

- **PASS ciblé** : exécution de méthodes source `MAJ()`, requêtes réelles SQLite en mémoire, données/étiquettes contrôlées indépendamment pour les 33 objets, à des niveaux limités et distincts. L'exécution de tests sur runner Windows n'est **pas** une recette de Noethys installé.

Les doublons de consommations, comptes payeurs multiples, annulations, filtres, caisses inconnues, mutations de paramètres et isolations de connexions sont échantillonnés par le banc.
- **PARTIEL** pour les graphes : axes `pie()`, `bar()` et `plot()` capturés. Aucun rendu Matplotlib natif, image MemoryFS individuelle, HTML ou aperçu réel n'est qualifié ; rendu de graphes certifié dans l'exécutable **0/15**.
- **QF :** les quatre objets (#30–33) sont exercés individuellement (SQLite + MAJ), mais **aucun type de QF ni règle multi-activités/multi-barèmes n'a été validé sur le plan métier**. Les valeurs égales de types différents sont agrégées numériquement par le code ; `Graphe_qf_defaut` omet visuellement `pasqf` et `a_verifier`, alors que les tableaux les comptent. Ne pas assimiler `a_verifier` à zéro.
- **Aucun** parcours imprimé ou zoomé en application installée n'est qualifié. `#432` : réactivité/focus/maximisation encore soumis à recette sur poste.
